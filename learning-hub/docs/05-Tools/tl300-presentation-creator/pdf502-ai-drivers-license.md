```
## 1.5 The AI Divide — Four Dimensions of Access

Not a simple "included vs. excluded." A student can be included
on some dimensions and excluded on others:

- Motivational access — does the student want to engage with AI,
  or actively avoid/distrust it?
- Material access — reliable device, data, electricity
- Skills access — knows how to prompt, verify, iterate
- Usage access — is actually permitted or encouraged to use AI in
  their own context (home, hostel, classroom norms)

Assuming uniform access across a socioeconomically mixed student
body will systematically disadvantage some students in AI-based
assignments.
─────────────────────────────────────

FACILITATOR NOTES:
Ask faculty: "Of your current class, do you actually know which
students have reliable data or device access after 9pm?" Most
will not. Flag this as something the Course Audit should surface
explicitly, not assume away.
```

```
SLIDE 2.4
─────────────────────────────────────
## Automation Bias

Humans systematically over-trust automated and algorithmic output
— even experts, even when they know the system is imperfect.

This is not only a student problem. Faculty are equally susceptible
when grading or research-assisting with AI.

Discussion: has AI output ever seemed "obviously right" to you
because it was fluent and confident — before you actually checked it?
─────────────────────────────────────

FACILITATOR NOTES:
Include faculty in the risk, not just students — this builds
credibility and models the humility you want them to teach.

"Provide a brief, plain-language, one-paragraph summary of the

citations."
```

```
SLIDE 2.5
─────────────────────────────────────
## Prompt Engineering — A Dialogue, Not a Single Shot

Starting template:
Role + Context + Task + Constraints + Format

Real prompting is iterative:
1. Draft a prompt using the template
2. Read the output critically
3. Refine — add missing context, tighten constraints, ask for a
   different angle
4. Repeat until the output actually meets the need

Step 1 is a starting scaffold. Steps 2–4 are the actual skill.
─────────────────────────────────────

FACILITATOR NOTES:
Emphasize that stopping at step 1 teaches a false idea of what
good AI use looks like. If time allows, have faculty pairs run a
real 3-round refinement live and compare the first output to the
final one.

ADDITIONAL CONTENT PROMPT:
"Generate one example 3-round prompt refinement sequence for the
task 'write a project brief for a final-year engineering capstone
project on solar-powered water pumps' — show the initial one-shot
prompt, a short critique of its output's weaknesses, a refined
second prompt, and a further refined third prompt, so faculty can
see the iteration process modeled step by step."
```

```
SLIDE 2.6
─────────────────────────────────────
## Evaluating AI Output — A Durable Method

For any AI output, from any tool, check:
- Accuracy — is it actually correct? Verify independently.
- Completeness — what is missing that a full answer would include?
- Creativity — is this a genuinely novel angle, or the most
  statistically likely answer?
- Reliability — would this hold up if you asked the same question
  three different ways?

This method outlasts any single tool. Apply it to whatever AI
tools you currently use.
─────────────────────────────────────

FACILITATOR NOTES:
If you want a live exercise, have faculty run the same prompt
through whatever tools they have access to and apply this four-part
check to each output.

ADDITIONAL CONTENT PROMPT:
"Generate one sample AI-written answer (150-200 words) to the
question 'Explain the causes of urban flooding,' along with a
completed four-part evaluation (Accuracy, Completeness, Creativity,
Reliability) applied to that sample answer, to model what a
completed evaluation looks like before faculty attempt one
themselves."
```

```
SLIDE 2.7
─────────────────────────────────────
## Ethics in Practice — Two Scenarios

Scenario A — Intellectual Property
A student submits code where a large, functioning chunk was
AI-generated verbatim, undisclosed. Is this different from copying
a chunk from an online forum, undisclosed? What makes it the same
or different?

Scenario B — Privacy
A faculty member pastes a student's exam answer, including their
name, into a public AI chatbot to check for plagiarism patterns.
What is the actual privacy exposure here, and what should have
been done instead?

Discuss in pairs: what policy would prevent each scenario, and
where should that policy live?
─────────────────────────────────────

FACILITATOR NOTES:
Scenario B is deliberately about faculty behavior, not only
student behavior. Bias and transparency can be woven into
discussion naturally — ask "where is the bias risk in Scenario A?"
(whose coding style or idiom gets flagged as 'suspicious' versus
'normal' by a pattern-detection tool) as a natural extension.

"Generate 2 additional short ethics scenarios (3-4 sentences each)
```

## MODULE 3: Designing Lovable Assignments

```
SLIDE 3.1
─────────────────────────────────────
# Module 3: Designing Lovable Assignments

Core principle: Students learn more deeply when they enjoy
meaningful work — and they will do it themselves rather than
delegate to AI, because delegating would mean missing out on
something they actually want to do.

Two different defenses against AI outsourcing exist side by side
in this program:
- LOVABLE (this module) — psychological: why would I skip the
  part I enjoy?
- AI-Resistant / AI-Proof design (Module 4) — structural: the
  task cannot be skipped and still pass

Both matter. Neither replaces the other.
─────────────────────────────────────

FACILITATOR NOTES:
Write both defense types on the board and leave them visible for
the rest of the module — this distinction prevents faculty from
seeing Module 3 and Module 4 as redundant or competing.
```

```
SLIDE 3.2
─────────────────────────────────────
## The LOVABLE Framework

- L — Learner Agency: the student chooses direction or approach
- O — Originality: the output cannot be a template fill-in
- V — Voice: the student's own perspective is visible in the result
- A — Authentic Audience: someone real, beyond the grader, will see it
- B — Build/Create: the student makes something, not just explains it
- L — Local Context: grounded in a real, nearby, tangible problem
- E — Engagement: the task holds attention because it genuinely matters

The two L's are distinct. Learner Agency is about whose CHOICE the
assignment reflects. Local Context is about whose PROBLEM it is.
An assignment can have one without the other.

See the Theoretical Foundations Appendix for the research base
behind this framework (Self-Determination Theory, Flow Theory,
Situated Learning, Interest Development).
─────────────────────────────────────

FACILITATOR NOTES:
State the two-L distinction aloud, do not leave it only on the
slide. Ask faculty for a quick example of an assignment with
agency but not local context (e.g., "pick any topic you like,"
with no real-world grounding), and one with local context but not
agency (e.g., "analyze this specific local case study," with no
choice in approach). This cements the distinction quickly.

ADDITIONAL CONTENT PROMPT:
"Generate a short, light, faculty-friendly meme concept (image
description + caption text, no actual image) contrasting a
'traditional assignment' with a 'LOVABLE assignment' — tone should
be gently humorous, workplace-appropriate, suitable for a higher-ed
faculty workshop slide. Provide 2 variations."
```

```
## A Note on Rigor

A fun assignment is not automatically a rigorous one. Enjoyment
and learning depth are related but not identical.

Before finalizing a LOVABLE-redesigned assignment, ask:
- Does this still require the core disciplinary skill the original

- Could a student complete this successfully while missing the
```

## MODULE 4: AI-Resistant to AI-Ready Assessment

```
SLIDE 4.1
─────────────────────────────────────
# Module 4: Designing Assessment That Cannot Simply Be Outsourced

Purpose: Design assessment that verifies genuine learning — not
assessment that is theoretically "unbeatable," but assessment
where outsourcing is either impractical, detectable, or
pedagogically self-defeating.

By the end of this module, you will be able to:
- Place any assessment on the AI-Resistant → AI-Proof → AI-Ready →
  AI-Native spectrum
- Design a scalable, multi-tier verification process for your
  own assessments
- Explain the validity/reliability trade-offs of performance-based
  assessment, and how to manage them
─────────────────────────────────────

FACILITATOR NOTES:
Set expectations early: no assessment is literally impossible to
outsource. The goal is to make outsourcing hard enough, detectable
enough, or pointless enough that a student is better off doing the
work themselves. This module gives you a spectrum and a mechanism,
not a guarantee.
```

```
SLIDE 4.2
─────────────────────────────────────
## A Spectrum, Not a Single Label

- AI-Resistant — difficult to outsource; requires real effort to
  fake convincingly
- AI-Proof — very hard to outsource without direct, observable
  human performance
- AI-Ready — designed assuming AI collaboration; the task requires
  human judgment ON TOP of AI assistance
- AI-Native — an entire course or curriculum assumes AI
  participation throughout, not just in individual tasks

Most of your existing assessments can be moved one step up this
spectrum without a complete redesign.
─────────────────────────────────────

FACILITATOR NOTES:
Avoid the word "proof" implying certainty — even a viva can be
gamed by a memorized script. Frame this as a spectrum of increasing
difficulty and decreasing payoff for outsourcing, not an absolute
guarantee. This framing keeps the module honest and credible.
```

```
SLIDE 4.3
─────────────────────────────────────
## Four Assessment Approaches

Observation-Based
- Laboratories, field visits, site studies, internship tasks

Performance-Based
- Viva, presentation, debate, demonstration

Process-Based
- Draft reviews, learning journals, design iterations, reflection logs

Context-Based
- Local interviews, community projects, field data collection,
  proprietary datasets

Each approach shifts what is being verified: not just the final
answer, but the process, the performance, or the setting that
produced it.
─────────────────────────────────────

FACILITATOR NOTES:
Ask faculty to identify, for their own course, one assessment that
could move from a pure written submission into one of these four
categories without changing the underlying learning objective.
```

```
SLIDE 4.4
─────────────────────────────────────

Engineering
Instead of: "Write code."
Use: "Defend your algorithm choices in a viva."

Business
Instead of: "Write a marketing plan."
Use: "Interview real local businesses and base your plan on what
you find."

Science
Instead of: "Submit a lab report."

Notice: the underlying skill being tested does not change. What
changes is how it is verified.
─────────────────────────────────────
```

```
SLIDE 4.5
─────────────────────────────────────
## The Validity and Reliability Problem

Performance-based assessment (viva, presentation, demonstration) is
harder to fake — but introduces new problems:

- Rater consistency — will two faculty score the same viva the
  same way?
- Time cost — a 15-minute viva per student does not scale to a
  200-student cohort
- Fairness — confidence, accent, and communication style can
  distort scoring independent of actual understanding

Moving to performance-based assessment without addressing these
issues trades one validity problem for another.
─────────────────────────────────────

FACILITATOR NOTES:
Do not skip this slide or treat it as a footnote — this is the
single biggest reason faculty resist performance-based assessment,
and dismissing the concern will cost you credibility in the room.
Acknowledge it fully before presenting the solution.
```

```
SLIDE 4.6
─────────────────────────────────────
## The Tiered Verification Model

A three-tier structure that scales fairness and rigor together:

Tier 1 — Self-Assessment (100% of students)
Every student scores their own submission against the course
rubric before submitting. Cheap, catches the weakest cases early,
and creates a record of the student's own thinking.

Tier 2 — AI-Conducted Viva (100% or most students)
An AI system asks 3–5 follow-up questions generated specifically
from THIS student's submission — not from a fixed question bank.
This checks understanding beyond the static submission, at a scale
no faculty member could match alone.

Tier 3 — Expert Viva (a defined subset only)
Reserved for: students flagged by Tier 2 as inconsistent or
borderline, students seeking top-band or portfolio-grade
credentialing, and a random audit sample for quality assurance.

Faculty time is spent where it matters most — not spread evenly
regardless of stakes.
─────────────────────────────────────

FACILITATOR NOTES:
This is the core mechanism of the entire module — spend the most
time here. Make the trigger criteria for Tier 3 explicit and public
from day one (for example: bottom 15% and top 15% of Tier 2 scores,
plus a 10% random audit) so students see the system as transparent,
not arbitrary. On a 10% sample of Tier 3 vivas, have two faculty
independently score the same session and compare — this catches
rater drift early and cheaply.

Safeguard to raise explicitly: what stops a student from having
another AI answer the Tier 2 viva questions for them in real time?
Mitigations include synchronous, camera-on delivery, and questions
generated live rather than drawn from any reusable bank.
```

```
SLIDE 4.7
─────────────────────────────────────
## Why This Concentrates Rigor Where It Is Needed

Rater inconsistency matters most at the edges of a grade
distribution — borderline pass/fail, and borderline top marks.
Tier 3 concentrates expert human attention exactly there.

The middle of the distribution, where the consequences of small
scoring differences are lower, is handled by Tiers 1 and 2.

This is a deliberate, risk-based allocation of your most limited
and valuable resource: expert faculty time.
```

# PART B: APPENDIX — THEORETICAL FOUNDATIONS FOR LEARNING

*This appendix is written as a reference document, not as slides.
It provides the research grounding behind the frameworks used
throughout Modules 1–6, for facilitators and faculty who want to
understand the mechanisms behind the tools, or who need to defend
the program's design choices to skeptical colleagues or
accreditation reviewers.*

## Introduction

Every framework used in this certification program — LOVABLE, the
Tiered Verification Model, Shift Up and Left, the Course Audit — is
a practical simplification of one or more established bodies of
research in learning science, motivation psychology, and assessment
theory. This appendix names those bodies of research explicitly,
explains their core claims in plain language, and states which part
of the program each one supports. It also notes, honestly, where
a theory has limits or where its application in this program is a
simplification rather than a direct implementation.

The theories are grouped into two sets: those primarily concerned
with **motivation and engagement** (why students want to do
something), and those primarily concerned with **learning and
retention** (how understanding actually forms and lasts). Module 3
draws mainly on the first set; Modules 1, 2, 4, and 5 draw mainly
on the second.

---

## Part 1: Motivation and Engagement

### Self-Determination Theory (Deci & Ryan)

**Core claim:** Human motivation is strongest and most durable when
three basic psychological needs are met: autonomy (a sense of
choice and ownership over one's actions), competence (a sense of
being capable and improving), and relatedness (a sense of
connection to other people through the activity).

**Why it matters here:** This is the strongest theoretical anchor
for the LOVABLE framework. Learner Agency corresponds directly to
autonomy. Build/Create paired with an achievable level of challenge
corresponds to competence. Authentic Audience and Voice correspond
to relatedness — the sense that real people, not just a grader,
will encounter the work.

**Where it applies in this program:** Module 3 (Designing Lovable
Assignments), directly.

**A limitation to hold in mind:** Self-Determination Theory explains
why a task can feel motivating. It does not, by itself, guarantee
the task is teaching the right disciplinary content — that check is
handled separately in Module 3's "Note on Rigor" slide, and is a
reminder that motivation theory and learning-outcome validity are
two different concerns that both need attention.

---

### Flow Theory (Csikszentmihalyi)

**Core claim:** People experience a state of deep, absorbed
engagement — "flow" — when the challenge of a task closely matches
their current skill level. Too easy, and the task produces boredom;
too hard, and it produces anxiety. Flow requires clear goals and
fast feedback on progress.

**Why it matters here:** Explains why hands-on Build/Create tasks
often feel different from passive explanation tasks — a
well-pitched challenge level is part of what makes an assignment
"lovable" rather than merely permitted. It also gives a diagnostic
question faculty can ask when a LOVABLE assignment isn't landing:
is it too easy (routine, disengaging) or too hard (overwhelming,
demotivating) for this particular cohort?

**Where it applies in this program:** Module 3, as a design check
alongside Self-Determination Theory.

**A limitation to hold in mind:** Flow is highly individual — the
same task can be "flow" for one student and either boring or
overwhelming for another in the same class. This is an argument for
building some choice or difficulty-scaling into LOVABLE assignments
rather than assuming one fixed version suits an entire cohort.

---

### Situated Learning and Legitimate Peripheral Participation (Lave & Wenger)

**Core claim:** Learning is not primarily an individual, abstract
process — it happens through participation in real communities of
practice, working on real problems alongside more experienced
practitioners, even if only at the periphery of that practice at
first.

**Why it matters here:** This is the theoretical grounding for both
Local Context and Authentic Audience in LOVABLE. An assignment
grounded in a real, nearby problem, reviewed or witnessed by a real
audience, is closer to genuine situated practice than an abstracted
textbook exercise — even if the student is still a novice.

**Where it applies in this program:** Module 3 (Local Context,
Authentic Audience), and indirectly Module 4's Context-Based
assessment category (local interviews, community projects).

**A limitation to hold in mind:** True situated learning usually
involves sustained participation over time, not a single
assignment. A one-off "local context" task borrows the spirit of
this theory without fully realizing it — worth being honest about
this with faculty rather than overclaiming.

---

### Interest Development Model (Hidi & Renninger)

**Core claim:** Interest develops in four phases: triggered
situational interest (a one-off spark), maintained situational
interest (sustained by external structure), emerging individual
interest (the learner begins voluntarily returning to the topic),
and well-developed individual interest (a durable, self-sustaining
interest independent of the original trigger).

**Why it matters here:** A single "lovable" assignment is, at best,
a trigger for situational interest. Whether it develops into lasting
individual interest depends on what happens afterward — follow-up
opportunities, further choice, continued relevance. This model gives
faculty a way to think about LOVABLE assignments as a starting point
across a course or program, not a one-time event with guaranteed
lasting effect.

**Where it applies in this program:** Module 3, as a longer-term
framing for why LOVABLE design should recur across a course rather
than appear once.

---

## Part 2: Learning, Memory, and Assessment Design

### Cognitive Load Theory (Sweller)

**Core claim:** Working memory is limited. Learning is impaired when
unnecessary mental effort (extraneous load) crowds out the effort
needed to actually process new material (germane load). Well-designed
instruction manages this by reducing extraneous load and pacing
germane load appropriately.

**Why it matters here:** Directly relevant to Module 2's prompt
engineering and AI evaluation content. Faculty and students both
face real cognitive load when learning to verify AI output — asking
someone to evaluate accuracy, completeness, creativity, and
reliability all at once, on unfamiliar material, is a real load
management problem. The four-part evaluation method in Module 2 is,
in effect, a worked structure designed to reduce that load by giving
evaluators a fixed checklist rather than an open-ended judgment call.

**Where it applies in this program:** Module 2 (AI Evaluation,
Prompt Engineering).

---

### Retrieval Practice (Roediger & Karpicke)

**Core claim:** Actively recalling information from memory —
rather than passively re-reading or re-reviewing it — produces
stronger, more durable learning. This is sometimes called the
"testing effect."

**Why it matters here:** Directly relevant to Module 4's shift
toward viva and performance-based assessment. A viva, by its nature,
requires a student to retrieve and articulate understanding in real
time rather than recognize a correct answer on a page — this is a
retrieval-practice-aligned format, which is part of why it also
tends to reveal genuine understanding versus surface familiarity.

**Where it applies in this program:** Module 4 (viva-based Tiers 2
and 3 of the Tiered Verification Model).

---

### Desirable Difficulties (Bjork)

**Core claim:** Certain kinds of difficulty during learning — ones
that feel effortful and slower in the moment — actually improve
long-term retention and transfer, compared to conditions that feel
smooth and easy at the time but produce weaker lasting learning.
Not all difficulty is desirable; difficulty caused by poor
instructional design (confusion, unclear goals) is not the same as
difficulty caused by productive struggle.

**Why it matters here:** Gives Module 4's rationale for
process-based and performance-based assessment a firmer footing —
these formats are often more effortful for students than a
multiple-choice exam, and that added effort, if it is the
*productive* kind, is part of what makes the learning last. This
also gives faculty language to explain to students why a more
demanding assessment format is a deliberate pedagogical choice, not
an arbitrary added burden.

**Where it applies in this program:** Module 4, as the rationale
for choosing observation-, performance-, and process-based
assessment over purely written formats.

**A limitation to hold in mind:** The difficulty has to be the right
kind. A confusing or badly designed viva is not a desirable
difficulty — it is just an obstacle. This is one more argument for
Module 4's emphasis on clear, published rubrics and transparent
Tier 3 trigger criteria: difficulty should come from the cognitive
demand of the task, not from ambiguity about what is expected.

---

### Metacognition and Self-Regulated Learning (Flavell; Zimmerman)

**Core claim:** Learning improves when learners actively monitor
and regulate their own understanding — planning their approach,
monitoring their progress, and evaluating their own output — rather
than only producing work for someone else to judge.

**Why it matters here:** This is the direct grounding for Tier 1 of
the Tiered Verification Model (student self-assessment against the
rubric before submission) and for the Visible Thinking / reflection
elements built into the Capstone (reflection logs, the Mother of
All Assignments' documented thinking process). Requiring students to
self-assess and document their own reasoning is not just an
administrative check — it is a direct exercise of metacognitive
skill, which independently improves learning outcomes.

**Where it applies in this program:** Module 4 (Tier 1
self-assessment), Module 5 (Mother of All Assignments' documented
thinking), Module 6 (reflection reports in the Capstone).

---

### Transfer of Learning

**Core claim:** Learning that occurs in one context does not
automatically apply in a different context. "Near transfer" (applying
a skill to a very similar new situation) is relatively common;
"far transfer" (applying a skill to a substantially different
situation) is much harder to achieve and requires deliberate design
— varied practice contexts, explicit comparison across situations,
and abstraction of underlying principles rather than memorization
of a single worked procedure.

**Why it matters here:** Directly relevant to Module 1's Course
Audit and Module 6's curriculum mapping. An assignment redesigned
in one course does not automatically mean a student can apply the
same judgment in a different course or in the workplace — this is
the argument for why curriculum-level redesign (Module 6) matters
beyond individual assignment-level redesign (Modules 3–5), and why
the Shift Up and Left target zone (origination and judgment) is
pursued as a recurring pattern across a program, not a single
course event.

**Where it applies in this program:** Module 1 (Course Audit),
Module 6 (Curriculum Mapping Exercise, whole-course and
whole-curriculum redesign rationale).

## A Note on Honest Use of Theory

None of the frameworks in Modules 1–6 are direct, literal
implementations of the theories above — they are practical design
tools inspired by and consistent with this research. Facilitators
should represent this relationship accurately: the theories explain
*why* the practical tools are reasonable design choices, not that
the tools are validated interventions in their own right. Where a
department or reviewer asks for evidence of impact, the honest
answer is that the tools are theory-informed by design, and their
actual effectiveness across the institution should be tracked through the Success
Metrics and Capstone pilot data described in Module 6 — not assumed
from the theory alone.
